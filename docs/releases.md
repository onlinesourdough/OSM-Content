# Method releases

## v0.14.0 · proposed, revised 24 November 2026

Defines Content as an optional operating model beside OSM-plugin: requirements, best practices and adaptable skeletons. Notion is the default; equivalent external records and human workflows remain valid. Reuses the plugin's base Knowledge/Content records and minimum-schema binding, with optional Foundation views and clear Knowledge status meanings.

Keeps two axes: five responsibilities plus one small channel working method that fits the channel, vision and channel goal. Makes the replicable content-channel skeleton primary. Newsletter, LinkedIn, X and the already-added YouTube are thin example copies; no growing channel catalogue is required. Newsletter reuse is an optional helper; owner choices are not shared workflow rules.

Keeps the schedule planning skeleton using an owner-selected cadence entry and optional horizon, without prescribed rhythm or activated jobs. Documents a short approval window for the next few days and owner–assistant review ping-pong as optional best practice. Generalizes the quality gate, comment resolution and commentable drafts before owner review. Only the owner marks final version/destination approval; use the existing review section or an equivalent field, with no new required Select. Second-model review is optional and names no model.

Rewrites the public guide around the operating model, base records and building an owner's setup. Keeps the earlier illustrations collapsed and preserves native child/catalogue/media references for the existing sync contract. Adds one bound native content-channel Draft with portable supporting references and a verified ZIP. The public publisher expands from eight to nine exact owned targets, keeping the five earlier packets frozen and core/private targets excluded. The guide explains core foundation handoff and shows one fictional workshop example of the responsibility loop. This method release does not move or rewrite private owner records.

The five v0.10.0 packets remain byte-for-byte frozen. Later templates retain edition 2026-11-24.1 except the channel skeleton, its four example copies and schedule, refined as edition 2026-11-24.2. The prior revision remains at `48d43e52dc9e9a26982a6b9b2c7543c39be0ab94`, and the initial 2026-11-23.1 proposal remains at `4ba3669375bbb5400965498bad1e0a63ff3ce0d4`. This proposal is not a release, native-adoption proof or complete style calibration, and publishes nothing.

## v0.13.0 · 22 November 2026

Adds a writing-voice workflow: selected genuine examples, minimal editing,
scoped owner corrections and separate evidence, delivery and standing-rule
approval. Five fictional acceptance cases exercise this guidance; they are not
a cross-model benchmark or proof of a particular owner’s complete voice profile.

Content setup reuses core 0.35.0’s four foundation outcomes and single schema
authority. The editorial methods remain optional, older template packets remain
frozen at v0.10.0, and external originals or deferrals are preserved.

An optional open icon family makes the four existing databases recognizable
without a required dashboard or new stores. The original paper mark is retained
for Knowledge; the Content mark becomes a brush with an orange stroke.

Use Notion’s native inline-code serialization for the example filename in the

## v0.12.2 · 20 November 2026

Bound anonymous readback retries to three fresh reads within the original
285-second window, allowing Notion’s public projection to catch up after a
confirmed API write. Reconciliation runs once; no write is retried. A persistent
public mismatch still holds activation.

The Content guide now has a visible mobile diagram, a folded wide version and
editable HTML source. Existing Knowledge roles, optional personal methods and
Source/Content/Edition records are distinct. A brief is a plan, not actual
material; references and decisions arise from real work. Only the root diagram
section received a deliberate authored handoff; native children, catalogue and
the seven other page baselines are preserved.

The default-foundation proposal remains separate in Content #7 / core #131.
Frozen template packets and their source/version provenance are unchanged.

## v0.12.1 · 20 November 2026

The anonymous public reader now checks the text actually shown for numbered
lists and fenced code instead of expecting CSS list numbers or the code
language selector. Literal numbered text inside code remains checked. The
complete API body, native references and five bound catalogue entries retain
their separate checks. The setup guide renders `vision.md` as a filename.

This patch does not change the optional-method boundary, install a Content
plugin or introduce the proposed default Content foundation. That separate
core contract change is tracked in [Content #7](https://github.com/onlinesourdough/OSM-Content/issues/7).
The five frozen v0.10.0 template packets remain unchanged.

## v0.12.0 · 20 November 2026

Automatic synchronization of the eight bound public Content guide/template
pages after validated main changes and releases. Reuses the pinned OSM public
API transport and anonymous browser reader. Source versions, native children,
catalogue, files and frozen templates are preserved. A changed human original
or incomplete read holds the update. Lost write replies are reconciled without
repeating the write, and an unchanged replay sends no API writes.

Channel-role examples include newsletter/email as a first-class channel and reuse
existing direction, goals, perspective and style records for personal setup.
The selected editorial-paper icon replaces the OSMC lettering.

References now retain a concrete reason per link and a relevant timestamp, so
saved examples remain useful rather than becoming an unannotated clip collection.

Activation is recorded only after a real bounded write, whole-set readback and
zero-write repeat. This infrastructure does not publish the owner's own content.

## v0.11.0 · 20 November 2026

First tagged release of this separate method repository. The earlier import
and reference-workflow change remain in Git history.

- A shorter entry and a practical workflow for a single post.
- Purpose, audience, language and ending selected per channel edition.
- Creative reference → own contribution → review → learning, using the
  existing Source, Content and Edition records.
- An explicit source-to-Notion map and release checks for relative links,
  source inventory and frozen template bytes. Saved Notion and anonymous public
  checks are recorded separately from offline validation.

The five v0.10.0 Draft templates and their original packet hashes are unchanged.
There is no new runtime, installed plugin, automatic Notion publisher or content
schedule. Voice calibration remains an evidence-based adoption task.
