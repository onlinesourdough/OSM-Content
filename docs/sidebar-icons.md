# A simple Notion sidebar

Use a small, consistent set of icons to make the existing home easier to scan.
The starter family is an optional visual treatment, not a required schema or
an instruction to create databases. Keep useful names, native hierarchy and
the business's own expression. A Content dashboard is optional; a linked view
does not need to become a second content store.

| Existing responsibility | Starter icon | Motif |
| --- | --- | --- |
| Knowledge | [PNG](../assets/icons/knowledge.png) | The established document motif |
| Memory | [PNG](../assets/icons/memory.png) | A database cylinder |
| Skills | [PNG](../assets/icons/skills.png) | A lightning bolt |
| Content | [PNG](../assets/icons/content.png) | A paintbrush and orange stroke |

The open motifs have no surrounding badge or frame. Warm ivory, dark espresso
and a restrained orange accent keep the family coherent; a business can replace
them with native Notion icons or its own assets. Apply icons to the actual
database pages, then inspect the sidebar at its normal small size. A generated
asset or successful API reply alone does not prove the icon renders there.

The AI operating model home can use the existing OSM mark or the adopting
business's own mark. Its icon does not imply a fifth database. The shared
[OSM plugin](https://github.com/onlinesourdough/OSM-plugin) owns its canonical
product mark; this family does not replace that mark.

When changing a home, preserve its records and integration-sensitive identities.
Move useful child pages and operational databases before removing an unwanted
dashboard, and update its actual references. Do not delete subscribers because
the owner no longer needs a Content overview.
