# Content setup

Template edition 2026-11-05.1. Use the owner’s actual Content configuration and routes. Read [adoption](references/adaptation.md) when tailoring this into a personal skill; normal use loads only the selected configuration and relevant material. This template is not an installed or enabled method.

Use the owner's selected context home and existing business foundation. Read its routes and working policy; find the current goals, ideal customers/audience, offers, positioning, voice and working preferences. Resolve only gaps that change the content work. Help a new creator choose; do not require a marketing vocabulary or invent strategic answers.

OSM owns that general foundation. This optional setup owns the content-specific collection, views/templates, workflow choices and configuration. Reuse a suitable existing collection and stable identities; inspect actual schema and integrations before a migration. The starter shape is one Content collection in the existing Notion foundation for sources, ideas/productions and independently editable editions. Local/cloud media and external editorial originals can retain their own mapped locations; Notion need not store large files. Read [the setup contract](references/setup-contract.md) when mapping a schema or configuration.

Read and link the goals and their revisions at their Knowledge owner. Resolve a missing or changed business goal through the core context method under the owner's authority; do not create a competing strategy. Configure formats, channels, source priorities, canonical text/media locations, tools, taste/voice references, handoffs and participation per stage: manual, assisted or automated. Keep personal configuration outside generic skills. A good existing analog workflow is a supported choice.

Notion editorial text and Kit newsletter delivery are a starter recipe; HyperFrames remains a video candidate, not a qualified default. Keep suitable existing tools. A recommended editor needs its own runtime qualification; do not install tools, connect accounts or enable cloud/model services just because Setup selected a candidate.

Verify that the selected Content collection and its routes are usable under the existing home policy and real provider grants. Follow core OSM's access contract for a gap, including intended descendants; do not redesign general permissions or silently widen accounts/sources.

Verify the chosen routes, record identity, useful views and one representative manual handoff. Repeating Setup should reuse the same originals. Report configured, authored, installed and actually exercised states separately.

Schedules are optional actions, not skill behavior. Configure one only under explicit applicable authority, with selected sources, output, trigger, action limits, uncertain-outcome handling and native job identity. Daily OSM upkeep can maintain this foundation without becoming a content publisher.
